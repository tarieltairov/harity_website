# Алтын Мурас

Сайт благотворительного фонда «Алтын Мурас»: главная, «О фонде», «Новости» с деталкой, «Проекты» с деталкой, «Отчёты», «Партнёры», «Контакты», поиск по сайту, страницы ошибок 404/500 и служебная страница UI-кита.

Проект на этапе вёрстки по макетам, бэкенда пока нет — все данные берутся из моков (`src/mocks`), разделённых по сущностям. Текущее состояние работ — в разделе [Статус работ](#статус-работ).

## Технологии

- **React 19** + **TypeScript**
- **Vite 8** — сборка и dev-сервер
- **React Router 7** — маршрутизация
- **SCSS-модули** — стили компонентов, глобальные токены в `src/styles`
- **clsx** — сборка классов; **vaul** — мобильная шторка (`BottomSheet`)
- **ESLint + Prettier** — линт и форматирование
- **Husky + lint-staged** — проверки перед коммитом
- **vite-plugin-checker** — ошибки ESLint оверлеем в браузере в dev-режиме

Пакетный менеджер — **Yarn** (в репозитории `yarn.lock`).

## Быстрый старт

```bash
# установка зависимостей
yarn

# запуск dev-сервера (по умолчанию http://localhost:5173)
yarn dev
```

## Маршруты

Пути и пункты навигации заданы в [src/config/routes.ts](src/config/routes.ts) — при добавлении страницы обновляйте `ROUTES` (и при необходимости `NAV_LINKS`), а не строковые литералы.

| Путь            | Страница                                |
| --------------- | --------------------------------------- |
| `/`             | Главная                                 |
| `/about`        | О фонде                                 |
| `/news`         | Новости                                 |
| `/news/:id`     | Деталка новости                         |
| `/projects`     | Проекты                                 |
| `/projects/:id` | Деталка проекта                         |
| `/reports`      | Отчёты                                  |
| `/partners`     | Партнёры                                |
| `/contacts`     | Контакты                                |
| `/search?q=`    | Результаты поиска                       |
| `/500`          | Страница ошибки сервера (для просмотра) |
| `/ui-kit`       | UI-кит (вне общего Layout)              |
| `*`             | 404                                     |

Все страницы, кроме `/ui-kit`, рендерятся внутри общего `Layout` (Header + хлебные крошки + Footer).

- **Пути деталок** не собираем строками — используем `getDetailPath(ROUTES.newsDetail, id)` / `getDetailPath(ROUTES.project, id)` из `routes.ts`: путь строится из паттерна роута через `generatePath`.
- **Хлебные крошки** рисует компонент `BreadCrumbs` в Layout, руками на страницах их не пишем. Названия разделов берутся из `NAV_LINKS`; для деталок есть словарь `CRUMB_LABELS` (см. `src/components/BreadCrumbs`) — по одной строке с резолвером названия на роут. На главной, `/search`, `/500` и 404 крошки не показываются.
- **Ошибки рендера.** `Layout` оборачивает `<Outlet />` в `ErrorBoundary` с фоллбеком — страницей `ServerError`. Ключ `key={location.pathname}` сбрасывает состояние ошибки при переходе на другой роут. Отдельный роут `/500` нужен, чтобы посмотреть страницу без падения.

Страницы подключены через `React.lazy` — каждая собирается в отдельный чанк и грузится при первом заходе на роут. Фоллбек на время загрузки — компонент `Loader`: внутри `Layout` он показывается вместо контента (шапка и подвал остаются), для роутов вне Layout — на весь экран (`Suspense` в `App.tsx`).

## Данные: типы и моки

Пока нет бэкенда, данные живут в двух папках, разбитых по сущностям (по файлу на сущность):

- [src/types/](src/types/) — интерфейсы: `NewsArticle` (+ `NewsPreview`, `ShareTarget`), `Project` (+ словарь `PROJECT_STATUS_LABEL`), `Partner`, `TeamMember`, `FundDocument` / `ReportsByYear`, `StatItem`, `FundContacts` / `SocialLink`, `SearchIndexItem` / `SearchSection`. Поля деталок и модалок (патч 2 макетов) — опциональные: `lead`, `body`, `gallery`, `stats` и т.д.
- [src/mocks/](src/mocks/) — данные: `NEWS_ARTICLES` (+ `NEWS_CATEGORIES`, `POPULAR_NEWS`, `SHARE_TARGETS`), `PROJECTS`, `PARTNERS`, `TEAM_MEMBERS`, `FUND_DOCUMENTS`, `REPORTS_BY_YEAR`, `FUND_STATS`, `FUND_CONTACTS`, `SOCIAL_LINKS`, моки поиска (см. ниже). Контент перенесён из макетов.

Правила:

- Захардкоженные массивы в страницах не заводим — данные добавляем в `mocks`, типы в `types`, страница импортирует из `@/mocks`.
- Связи между сущностями — по `id` (`relatedIds`, `newsIds`, `projectIds`); для выборки есть хелперы `getNewsById` / `getProjectById`.
- «Эталонные» записи с полным набором полей для деталок и модалок: новость `id: 1` (центр в Оше), проект `id: 2` (мобильные бригады), партнёр `id: 9`, член команды `id: 1`.
- Один источник — без копий: главная берёт `PROJECTS.slice(0, 3)` и `NEWS_ARTICLES.slice(0, 3)`, статистика и контакты фонда используются из одного мока на всех страницах.

Бэкенд разрабатывается параллельно по контракту от фронта: [docs/api-contract.md](docs/api-contract.md). При подключении API заменяется только слой `mocks`; отличия контракта от текущих моков перечислены в разделе 4 контракта.

## Бэкенд

API по контракту уже реализовано и лежит в отдельном репозитории: [tarieltairov/harity_website_backend](https://github.com/tarieltairov/harity_website_backend), локально — папка `../backend` рядом с этой (NestJS 12 + MongoDB). Его документация — `backend/docs/` (назначение, архитектура, справочник API с примерами, модель данных, установка, разработка). Запуск для фронта:

```bash
cd ../backend && yarn && yarn start:dev
```

Без `.env` он поднимается на `http://localhost:3000/api/v1` с MongoDB в памяти и тем же контентом, что в `src/mocks`; Swagger — `http://localhost:3000/api/docs`. Общая база команды — MongoDB Atlas, строка подключения выдаётся лично и кладётся в `backend/.env` (см. `backend/docs/05-setup.md`).

Фронт к API пока не подключён и продолжает работать на моках. Порядок подключения: слой `src/api/` вместо `mocks`, типы по контракту (раздел 4), затем страницы от простых списков к новостям, поиску и формам.

## Поиск

Поиск работает по клиентскому индексу `SEARCH_INDEX` из [src/mocks/searchIndex.ts](src/mocks/searchIndex.ts): он собирается из новостей, проектов и отчётов (тип записи — «Новость» / «Проект» / «Документ», год — для фильтра «Период»). Единый матчер `searchIndex(query)` используется и в оверлее шапки, и на странице результатов; запрос короче `MIN_SEARCH_QUERY_LENGTH` (2 символа) не ищется — так же, как в контракте.

- **Оверлей** (`Header`): до ввода — «Вы искали» (история в `localStorage`, ключ `altyn-muras-search-history`, стартовое наполнение из `RECENT_SEARCH_QUERIES`) и «Популярные разделы» (`POPULAR_SEARCH_SECTIONS` — это ссылки на разделы сайта, а не запросы); после ввода — три подсказки и ссылка «Все результаты» на `/search?q=`.
- **Страница результатов** (`SearchPage`): фильтры по типу материала (со счётчиками) и по году, подсветка совпадений, три пустых состояния (нет запроса / короткий запрос / ничего не нашлось). Десктоп и планшет — номера страниц (`Pagination` со стрелкой «назад»), мобильный — накопительная кнопка «Показать ещё». Пока по 5 результатов на страницу (макет экрана 11); с API размер страницы придёт с бэка.

## Модалки, шторки, состояния

- **`Modal`** (`ui/Modal`) — десктопное окно с анимацией закрытия, Esc и блокировкой скролла; **`BottomSheet`** (`ui/BottomSheet`, на базе `vaul`) — мобильная шторка. Паттерн «на десктопе модалка, на мобильном шторка» см. в `PersonCard` (карточка члена команды): переключение по `matchMedia('(max-width: 992px)')`, данные и флаг открытия хранятся отдельно, чтобы контент не пропадал раньше анимации закрытия.
- **`FeedbackModal`** — форма «Написать нам» (тема, имя, телефон с маской `+996`, e-mail, сообщение, согласие) с валидацией на фронте; после отправки открывает `SuccessModal`. Подключена на главной (CTA «Стать партнёром»).
- **`Gallery`** (`ui/Gallery`) — сетка фото с «+N» и лайтбоксом, используется на деталках новости и проекта.
- **Скелетоны**: примитивы `SkeletonText` / `SkeletonBlock` / `SkeletonCircle` (`ui/Skeleton`) и `ContentCardSkeleton`; у `ContentCard` есть пропс `isLoading`, при котором рендерится скелетон той же геометрии.
- **Подписка в футере**: `SubscribeBanner` + `SubscriptionStatus` (состояние «готово, проверьте почту»). Отправки на бэк пока нет.

## Дизайн-токены

Все цвета, типографика, радиусы и параметры сетки — CSS-переменные в [src/styles/variables.scss](src/styles/variables.scss). В стилях компонентов используйте токены (`var(--color-accent)`, `font: var(--font-h2)` и т.д.), а не «сырые» значения.

Ключевое:

- **Цвета** — в формате `oklch`, рядом в комментариях hex-эквиваленты из макетов. Есть группы для футера, шапки, форм (ошибка/успех), скелетонов и теней.
- **Шрифты** — `Lora` (заголовки, serif) и `Manrope` (текст, sans); готовые шорткаты `--font-h1`, `--font-h2`, `--font-body` и др.
- **Сетка** — контейнер `--container-width: 1440px`, боковые отступы `--container-padding`: 56px (desktop) / 28px (≤992px) / 18px (≤768px). За обёртку отвечает компонент `Container`.

## Качество кода

- Pre-commit хук (husky + lint-staged) прогоняет ESLint (`--max-warnings=0`) по `ts/tsx` и `prettier --check` по staged-файлам, включая `scss`, `json`, `html` и `md` — коммит с ошибками не пройдёт.
- В dev-режиме ошибки ESLint показываются оверлеем прямо в браузере (`vite-plugin-checker`); на сборку он не влияет.
- Перед пушем полезно запустить `yarn fix`, затем `yarn build`.
- Новый переиспользуемый компонент в `ui/` или `components/` сразу добавляется секцией на страницу `/ui-kit` (демо-данные — из `@/mocks`).
