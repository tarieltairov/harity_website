# Алтын Мурас

Сайт благотворительного фонда «Алтын Мурас»: главная, «О фонде», «Новости» с деталкой, «Проекты» с деталкой, «Отчёты», «Партнёры», «Контакты», поиск по сайту, страницы ошибок 404/500 и служебная страница UI-кита.

Вёрстка по макетам готова, фронт подключён к публичному API бэкенда (`../backend`): данные приходят с сервера через слой `src/api` (TanStack Query), моков больше нет. Текущее состояние работ — в разделе [Статус работ](#статус-работ).

## Технологии

- **React 19** + **TypeScript**
- **Vite 8** — сборка и dev-сервер
- **React Router 7** — маршрутизация
- **TanStack Query 5** — запросы к API, кеш по языку, состояния загрузки и ошибок
- **i18next + react-i18next** — локализация: кыргызский, русский, английский
- **SCSS-модули** — стили компонентов, глобальные токены в `src/styles`
- **clsx** — сборка классов; **vaul** — мобильная шторка (`BottomSheet`)
- **ESLint + Prettier** — линт и форматирование
- **Husky + lint-staged** — проверки перед коммитом
- **vite-plugin-checker** — ошибки ESLint оверлеем в браузере в dev-режиме

Пакетный менеджер — **Yarn** (в репозитории `yarn.lock`).

## Быстрый старт

```bash
# установка зависимостей
yarn

# бэкенд — в соседней папке (см. раздел «Бэкенд»)
cd ../backend && yarn && yarn start:dev   # http://localhost:3000/api/v1

# запуск dev-сервера (по умолчанию http://localhost:5173)
yarn dev
```

Адрес API задаётся переменной `VITE_API_URL` (по умолчанию `http://localhost:3000/api/v1`): шаблон — [.env.example](.env.example), своё значение — в `.env.local` (в репозиторий не попадает).

## Языки

Сайт на трёх языках — кыргызском, русском и английском. Язык — префикс в URL: `/ky/news`, `/ru/news`, `/en/news`; адрес без префикса (`/`, старые ссылки) открывается на последнем выбранном языке, иначе на языке браузера, иначе на русском. Переключатель — в шапке: он меняет только префикс в адресе, страница и её состояние (фильтры, формы, скролл) остаются на месте, «назад» возвращает на предыдущий язык.

- Словари интерфейса — [src/i18n/locales/](src/i18n/locales/) (`ru.ts` — эталон, по нему проверяются ключи в `ky.ts` и `en.ts`). В компонентах — `const { t } = useTranslation()` и `t('news.title')`. Захардкоженных текстов в компонентах нет — это касается и служебной страницы `/ui-kit`.
- Контент (новости, проекты, команда…) приходит с API на языке страницы: хуки из `src/api` сами добавляют `?lang=` к запросу и держат отдельный кеш для каждого языка, поэтому переключение туда-обратно не ходит на сервер повторно.
- Даты, периоды проектов и размеры файлов форматирует хук `useFormat()` — в данных лежат ISO-даты, месяцы `YYYY-MM` и байты.
- Кыргызский перевод — черновой, нужна вычитка носителем языка.

## Маршруты

Пути указаны без языкового префикса — его добавляет роутер. Пути и пункты навигации заданы в [src/config/routes.ts](src/config/routes.ts) — при добавлении страницы обновляйте `ROUTES` (и при необходимости `NAV_LINKS`), а не строковые литералы.

| Путь            | Страница                                |
| --------------- | --------------------------------------- |
| `/`             | Главная                                 |
| `/about`        | О фонде                                 |
| `/news`         | Новости                                 |
| `/news/:id`     | Деталка новости                         |
| `/projects`     | Проекты                                 |
| `/projects/:id` | Деталка проекта                         |
| `/reports`      | Отчёты                                  |
| `/partners`     | Партнёры                                |
| `/contacts`     | Контакты                                |
| `/search?q=`    | Результаты поиска                       |
| `/500`          | Страница ошибки сервера (для просмотра) |
| `/ui-kit`       | UI-кит (вне общего Layout)              |
| `*`             | 404                                     |

Все страницы, кроме `/ui-kit`, рендерятся внутри общего `Layout` (Header + хлебные крошки + Footer).

- **Пути деталок** не собираем строками — используем `getDetailPath(ROUTES.newsDetail, id)` / `getDetailPath(ROUTES.project, id)` из `routes.ts`: путь строится из паттерна роута через `generatePath`. Параметр `:id` разбирается `parseDetailId` — битый id (`/news/abc`) сразу даёт страницу 404 без запроса к API.
- **Хлебные крошки** рисует компонент `BreadCrumbs` в Layout, руками на страницах их не пишем. Названия разделов берутся из `NAV_LINKS`; для деталок есть словарь `CRUMB_LABELS` (см. `src/components/BreadCrumbs`) — по одной строке на роут, название берётся из того же запроса, что делает страница (общий кеш). На главной, `/search`, `/500` и 404 крошки не показываются.
- **Ошибки рендера и API.** `Layout` оборачивает `<Outlet />` в `ErrorBoundary` с фоллбеком — страницей `ServerError`. Ключ `key={location.pathname}` сбрасывает состояние ошибки при переходе на другой роут. Ошибки запросов (сервер недоступен, 5xx) попадают туда же автоматически — это настройка `throwOnError` в `src/api/queryClient.ts`; `NOT_FOUND` от API деталки превращают в страницу 404. Отдельный роут `/500` нужен, чтобы посмотреть страницу без падения.

Страницы подключены через `React.lazy` — каждая собирается в отдельный чанк и грузится при первом заходе на роут. Фоллбек на время загрузки — компонент `Loader`: внутри `Layout` он показывается вместо контента (шапка и подвал остаются), для роутов вне Layout — на весь экран (`Suspense` в `App.tsx`).

## Данные: типы и API

Данные приходят с бэкенда по контракту [docs/api-contract.md](docs/api-contract.md); на фронте за них отвечают две папки, разбитые по сущностям (по файлу на сущность):

- [src/types/](src/types/) — типы ответов API: `NewsListItem` / `NewsArticle` (+ `NewsPreview`, `NewsCategoryCount`), `ProjectListItem` / `Project` (+ `ProjectPeriod`), `Partner` / `PartnerDetails`, `TeamMember`, `DocumentFile` / `ReportsByYear`, `StatItem`, `Contacts` / `SocialLink`, `SearchItem` / `SearchResponse`, конверты `Paginated<T>` и `ApiErrorBody`. Подписи статусов и типов материалов живут в словарях `src/i18n/locales`, названия категорий новостей приходят с API.
- [src/api/](src/api/) — запросы и кеш на TanStack Query. `client.ts` — `request()` поверх `fetch` и класс `ApiError` (статус, код, ошибки полей); `queryClient.ts` — общие настройки кеша и ошибок; по файлу на сущность — хуки `useNewsList(params)`, `useNewsArticle(id)`, `useProjects(params)`, `useProject(id)`, `useReports()`, `useFundDocuments()`, `usePartners()`, `usePartner(id)`, `useTeam()`, `useStats()`, `useContacts()`, `useSearch(params)`, `useSearchSuggest(q)`; формы — `useSendFeedback()`, `useSubscribe()`. Язык страницы хуки подставляют сами.

Правила:

- Захардкоженные массивы данных в страницах не заводим — всё приходит с API; константы-списки (фильтры, темы формы, кнопки «Поделиться») хранят ключи словаря.
- Связи между сущностями бэк отдаёт развёрнутыми: у новости — `related`, у проекта — `news`, у партнёра — `projects`; резолвить по id на фронте не нужно.
- Загрузка: пока данных нет, страницы показывают скелетоны (`ContentCard isLoading`, `StatsBlock`, `SectionWithCards isLoading`) или `Loader`; при смене страницы или фильтра старые карточки остаются до прихода новых. Пустой список — короткое сообщение (`news.empty`, `projects.empty`).
- Ошибки: сеть и 5xx уходят в `ErrorBoundary` (страница 500), `NOT_FOUND` — страница 404. Компоненты вне `ErrorBoundary` (шапка, подвал, крошки, модалка «Написать нам», страница 500, UI-кит) передают хукам `throwOnError: false` и просто прячут блок без данных.
- «Эталонные» записи с полным набором полей для деталок и модалок (в сидах бэка): новость `id: 1` (центр в Оше), проект `id: 2` (мобильные бригады), партнёр `id: 9`, член команды `id: 1`.
- Один источник — без копий: контакты фонда (адрес, почта, телефон, соцсети) везде берутся из `useContacts()`, включая футер, модалку «Написать нам» и страницу 500.

## Бэкенд

API по контракту уже реализовано и лежит в отдельном репозитории: [tarieltairov/harity_website_backend](https://github.com/tarieltairov/harity_website_backend), локально — папка `../backend` рядом с этой (NestJS 12 + MongoDB). Его документация — `backend/docs/` (назначение, архитектура, справочник API с примерами, модель данных, установка, разработка). Запуск для фронта:

```bash
cd ../backend && yarn && yarn start:dev
```

Без `.env` он поднимается на `http://localhost:3000/api/v1` с MongoDB в памяти и контентом макетов; Swagger — `http://localhost:3000/api/docs`. Общая база команды — MongoDB Atlas, строка подключения выдаётся лично и кладётся в `backend/.env` (см. `backend/docs/05-setup.md`).

Фронт подключён ко всем эндпоинтам контракта: ленты новостей и проектов с серверной пагинацией и фильтрами, деталки, отчёты, партнёры, команда, цифры, контакты, поиск (подсказки и страница результатов), формы «Написать нам» и подписки. Известные нестыковки, которые ещё предстоит закрыть на бэке:

- темы и тексты ошибок формы «Написать нам» на бэке только по-русски: фронт отправляет русское значение темы из `FEEDBACK_TOPIC_VALUES`, а ошибки полей из ответа `400` показывает как есть;
- проверка имени на бэке не пропускает кыргызские буквы ң/ө/ү (фронт их допускает);
- форма на странице «Контакты» (экран 07) не отправляется — в ней нет телефона и темы, обязательных для `/feedback`.

## Поиск

Поиск делает бэкенд (`GET /search` и `GET /search/suggest`): индекс из новостей, проектов, документов и статических страниц сайта (тип записи — `news` / `project` / `document` / `page`). Константы на фронте — в [src/config/search.ts](src/config/search.ts): минимальная длина запроса (2 символа, как в контракте), список типов, «Популярные разделы», путь, куда ведёт результат. Подсветку совпадений и подпись-мету (дата, статус, «PDF · 2.4 МБ») собирает фронт.

- **Оверлей** (`Header`): до ввода — «Вы искали» (история в `localStorage`, ключ `altyn-muras-search-history`, пока истории нет — стартовое наполнение из словаря `search.recentSeed`) и «Популярные разделы» (ссылки на разделы сайта, а не запросы); после ввода — три подсказки с `/search/suggest` (запрос уходит с задержкой, не на каждый символ) и ссылка «Все результаты» на `/search?q=` со счётчиком `total`.
- **Страница результатов** (`SearchPage`): фильтры по типу материала (счётчики `counts` из ответа, не зависят от выбранного типа) и по году (`years` из ответа), подсветка совпадений, три пустых состояния (нет запроса / короткий запрос / ничего не нашлось). Десктоп и планшет — номера страниц (`Pagination` со стрелкой «назад»), мобильный — накопительная кнопка «Показать ещё» (страницы 1…N догружаются по очереди). Размер страницы — из ответа (по контракту 10).

## Модалки, шторки, состояния

- **`Modal`** (`ui/Modal`) — десктопное окно с анимацией закрытия, Esc и блокировкой скролла; **`BottomSheet`** (`ui/BottomSheet`, на базе `vaul`) — мобильная шторка. Паттерн «на десктопе модалка, на мобильном шторка» см. в `PersonCard` (карточка члена команды): переключение по `matchMedia('(max-width: 992px)')`, данные и флаг открытия хранятся отдельно, чтобы контент не пропадал раньше анимации закрытия.
- **`FeedbackModal`** — форма «Написать нам» (тема, имя, телефон с маской `+996`, e-mail, сообщение, согласие) с валидацией на фронте; отправляет `POST /feedback` и после ответа открывает `SuccessModal`, ошибки полей из ответа `400` показывает под полями. Подключена на главной (CTA «Стать партнёром»).
- **`Gallery`** (`ui/Gallery`) — сетка фото с «+N» и лайтбоксом, используется на деталках новости и проекта.
- **Скелетоны**: примитивы `SkeletonText` / `SkeletonBlock` / `SkeletonCircle` (`ui/Skeleton`) и `ContentCardSkeleton`; у `ContentCard` есть пропс `isLoading`, при котором рендерится скелетон той же геометрии.
- **Подписка в футере**: `SubscribeBanner` отправляет `POST /subscriptions` и показывает `SubscriptionStatus` («готово, проверьте почту»); повторный адрес для бэка — тоже успех.

## Дизайн-токены

Все цвета, типографика, радиусы и параметры сетки — CSS-переменные в [src/styles/variables.scss](src/styles/variables.scss). В стилях компонентов используйте токены (`var(--color-accent)`, `font: var(--font-h2)` и т.д.), а не «сырые» значения.

Ключевое:

- **Цвета** — в формате `oklch`, рядом в комментариях hex-эквиваленты из макетов. Есть группы для футера, шапки, форм (ошибка/успех), скелетонов и теней.
- **Шрифты** — `Lora` (заголовки, serif) и `Manrope` (текст, sans); готовые шорткаты `--font-h1`, `--font-h2`, `--font-body` и др.
- **Сетка** — контейнер `--container-width: 1440px`, боковые отступы `--container-padding`: 56px (desktop) / 28px (≤992px) / 18px (≤768px). За обёртку отвечает компонент `Container`.

## Качество кода

- Pre-commit хук (husky + lint-staged) прогоняет ESLint (`--max-warnings=0`) по `ts/tsx` и `prettier --check` по staged-файлам, включая `scss`, `json`, `html` и `md` — коммит с ошибками не пройдёт.
- В dev-режиме ошибки ESLint показываются оверлеем прямо в браузере (`vite-plugin-checker`); на сборку он не влияет.
- Перед пушем полезно запустить `yarn fix`, затем `yarn build`.
- Новый переиспользуемый компонент в `ui/` или `components/` сразу добавляется секцией на страницу `/ui-kit` (демо-данные — с API через те же хуки, что и на страницах).

## Ветки

Работаем по git flow:

- `main` — основная ветка, PR направляются в неё.
- `dev` — текущая ветка разработки.
- Фичевые ветки — `feat/<название>`, исправления — `fix/<название>` (см. историю PR).
